*** HOW TO ADD GAMES ***

[Back to the game log]

How it works

All the games live in one file, games.json. The page you see, index.html, is generated from that file by the script tools/build_site.py. So:

  • Change games.json, never index.html (your edits to it would be overwritten).
  • Every way of adding a game below rebuilds index.html for you.

Option 1: the script (recommended)

The script tools/add_game.py adds, updates and removes games. When it adds one it looks the game up on RAWG and saves the cover, the trailer (when RAWG has one) and the screenshots. It needs Python 3 and nothing else.

One-time setup

  1. Get a free key at rawg.io/apidocs.
  2. Copy .env.example to .env and put your key in it: 
    RAWG_API_KEY=your-key-here
Careful: .env is listed in .gitignore, so it is never uploaded to GitHub. Keep it that way. Never paste the key into a page or commit it.

Add a finished game

python3 tools/add_game.py "Hades" --platform PS5 --genre "Roguelike" --finished 2026-10-12

Add a game you are still playing

python3 tools/add_game.py "Sekiro: Shadows Die Twice" --platform PS4 --genre "Souls Like" --status "In progress"

If the script picks the wrong game

List the matches, then fix the game with the id you want:

python3 tools/add_game.py "Resident Evil" --search
python3 tools/add_game.py "Resident Evil" --update --refresh --rawg-id 56183

Update a game

Add --update and give only what changes. The title must match a game already in the list (capital letters do not matter).

python3 tools/add_game.py "Sekiro: Shadows Die Twice" --update --status Done --finished 2026-11-02
python3 tools/add_game.py "Hades" --update --platform PC --notes "Played twice"

Use --status Done to move a game from "In progress" to finished (give --finished if it has no date). Use --refresh to fetch the cover, trailer and screenshots again.

Remove a game

python3 tools/add_game.py "Hades" --remove

All options

OptionMeaning
--platformPlatform you played on, for example PS5, SNES, PC.
--genreGenre text shown on the page.
--finishedDate finished as YYYY-MM-DD.
--status"In progress" for unfinished games, or Done to mark a game as finished. Leave it out when adding a finished game.
--notesOptional short note shown under the game.
--rawg-idExact RAWG game id, to skip the search.
--searchOnly list the RAWG matches and stop.
--updateChange the given fields of a game that is already in the list.
--removeRemove the game from the list.
--refreshWith --update: fetch the cover, trailer and screenshots again.

Option 2: manage games from GitHub (no computer needed)

The repository has a workflow that runs the same script for you. You fill in a form on GitHub and the site updates by itself a minute later. It can add, update and remove games.

One-time setup

  1. In the repository open Settings, Secrets and variables, Actions, press New repository secret, name it RAWG_API_KEY and paste your RAWG key.
  2. Open Settings, Pages and set Source to GitHub Actions.

Use it

  1. Open the Actions tab, choose Manage games and deploy on the left, then press Run workflow.
  2. Pick an action and fill in the title. Fill in only the other fields that action needs.
  3. Press the green Run workflow button. The workflow saves the change to games.json, rebuilds index.html and publishes the site.
ActionWhat it does
addAdds a new game. Give a finished date, or type In progress in the status field.
updateChanges the fields you fill in for a game already in the list. Type Done in the status field to mark a game as finished. Tick refresh_media to fetch the cover, trailer and screenshots again.
removeRemoves the game. Only the title is needed.
searchLists the RAWG matches in the run summary and changes nothing.

If the wrong game is picked, run search to see the matches, then run update with the right id in rawg_id and refresh_media ticked.

The key is stored as a GitHub secret. It is never written to the site or the repository.

Option 3: edit games.json by hand

games.json is a list. Add one object per game, like this:

{
 "id": "hades",
 "title": "Hades",
 "platform": "PS5",
 "genre": "Roguelike",
 "finished": "2026-10-12",
 "notes": "Released in 2020.",
 "cover": "https://media.rawg.io/media/games/1f4/1f47a270b8f241e4676b14d39ec620f7.jpg",
 "trailer": "",
 "trailerPreview": "",
 "screenshots": []
}
FieldMeaning
idRequired. A short unique name in lowercase with dashes.
titleRequired. The name shown on the page.
platform, genreText shown on the page.
finishedDate as YYYY-MM-DD. The newest dates are listed first.
statusOptional. Add "status": "In progress" for games you have not finished. They are listed first and show Status instead of a date.
notesOptional text under the game.
coverA full image address, or a file in this project such as covers/hades.jpg. If it is empty, the page shows "[no picture]".
trailer, trailerPreviewOptional video file address and its poster image. Leave "" for none.
screenshotsA list of image addresses. Use [] for none.

Keep the commas between objects and use double quotes. If something looks wrong after an edit, check the file at jsonlint.com.

Then rebuild the page, because index.html is generated from games.json:

python3 tools/build_site.py

(When you push to GitHub, the publishing workflow also rebuilds the page, so the live site always matches games.json.)

Using your own cover image

Put the file in the covers/ folder, then set "cover": "covers/your-file.jpg". Keep images small (under about 300 KB) so the site stays fast.

Change or remove a game

To change a game, edit its object in games.json. To remove it, delete the whole object, including its trailing comma if it is the last one. The order never needs editing: the page sorts by date on its own. Then rebuild the page as shown above.

Look at it on your computer

The page is plain HTML with the data inside it, so just open index.html in your browser. You need an internet connection to see the pictures, because they come from RAWG.

Publish on GitHub Pages

  1. Create a repository on GitHub and push this folder to it. Check that .env is not included.
  2. In the repository, open Settings, Pages and set Source to GitHub Actions.
  3. Run the Manage games and deploy workflow from the Actions tab, or push any change to main. Every push to main publishes the site.
  4. After a minute the site is live at https://YOUR-USER.github.io/YOUR-REPO/.

To update the site later, add games, then commit and push:

git add games.json index.html covers
git commit -m "Add Hades"
git push

Good to know

  • Covers, screenshots and trailers from RAWG are loaded from RAWG's servers, and the page links back to RAWG as their terms ask. RAWG has trailers for few games, mostly newer ones. Older games often have screenshots only.
  • RAWG's main image is often a promotional picture, not a box cover. Use your own image in covers/ if you want real box art.
